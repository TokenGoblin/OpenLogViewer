# Defects found in the C# while porting it

Porting agents carried the C#'s behaviour over exactly, bugs included, so the two apps
agreed. Since 2026-11-08 (user decision) **the Rust fixes every bug listed here** instead of
copying it: each has a test that fails on the C#'s behaviour, and its "Found by" cell ends
"fixed in Rust" with a line saying what the Rust does now. The C# itself is not changed by
this. Each entry names where the defect is and how it was found.

| Where | Defect | Found by |
|---|---|---|
| **`MaxxTune.Write` (HIGH, shipping app)** | `TryAsk` doesn't discard input after its last failed attempt, and `Write` doesn't discard before sending the header, so a late telemetry reply's leading 0x80 can be read as the header ack. The real header ack is then taken as the payload ack, and **the write reports success even if the ECU refused the payload**. `Verify` discards first and would catch it, but only if a caller runs it. **Rust now:** Already fixed before this pass: `write` clears the input before the header and again before the payload; pinned by `a_stale_acknowledgement_does_not_turn_a_refused_payload_into_ok` (review_fixes). | w4-live review, **fixed in Rust** |
| **`TunerStudioSource.Recover` + `EcuConnection` (HIGH, shipping app)** | A port reopen between `WriteTunePage` and `BurnPage` (a poll-thread recovery) resets a Speeduino, so the written change is lost, and the burn then commits the unchanged tune **and reports success**. The read-back ran before the reset, so it can't catch it. Recovery also reads straight after the reset with no boot wait, into the bootloader. **Fixed in the C# on branch `fix-burn-after-reopen` (aecc523, 3c1896d), not yet merged to main.** **Rust now:** Already fixed before this pass: the connection remembers pages written before a reopen and refuses their burn (`a_burn_after_a_reopen_is_refused_because_the_written_change_is_lost`). | w3-connection review, **fixed in Rust** |
| `ChannelClassifier` (units check) | `Simplify` removes `/` and `°`, so the `"g/s"`, `"kg/h"`, `"lb/min"`, `"km/h"` and `"m/s"` arms can never match; only the slash-free spellings work. `"°"` simplifies to empty and is accepted for every role. **Rust now:** The Rust compares units with `simplify_units`, which keeps `/` and `:` and drops `°` unless it is the whole unit; the slashed arms now match, `m/s` is no longer `ms`, and a bare `°` suits only the angle roles. | w1-channels, **fixed in Rust** |
| `SafeFolder` | A safe folder at a filesystem root rejects every file: `Folder + separator` already ends in a separator. **Rust now:** The Rust adds a separator to the folder prefix only when it does not already end in one, so a folder at a filesystem root accepts plain names. | w0-base, **fixed in Rust** |
| `MathExpression` | Long runs of unary `-`, `!` or `^` are not depth-limited (only parenthesised nesting is capped at 64), so a hostile expression can overflow the stack. **Rust now:** The Rust counts runs of prefix `-`, `!`, `+` and `^` against the same 64-level limit as brackets, so they are a parse error, not a stack overflow. | w0-base, **fixed in Rust** |
| `TuningMath.Clamp` use | `Math.Clamp` throws when min > max; the Rust returns NaN instead, since bad input must not crash. **Rust now:** Already fixed before this pass: `clamp` with min > max is an unknown sample (NaN), pinned by `clamp_with_reversed_bounds_is_unknown_not_a_crash`. | w0-base, **fixed in Rust** |
| `SniperSession` | Node id read as `CanId & 0x7FF`; packing is `node << 3`, so it should be `(CanId >> 3) & 0x7FF`. Confirmed on hardware 2026-09-19. **Rust now:** The Rust reads the node as `(CanId >> 3) & 0x7FF` and addresses it; the pinned C# test is replaced by the formerly ignored correct one. **Needs the bench:** the C# defect is a hardware finding, so a real Sniper must confirm the corrected read. | hardware, **fixed in Rust** |
| `SniperCanTransport` | `PIPE_TRANSFER_TIMEOUT` never set, so a read on a quiet bus blocks forever. Confirmed on hardware. **Rust now:** Already fixed before this pass: the nusb reads carry a timeout (`a_quiet_bus_times_out_instead_of_blocking_forever`). **Needs the bench:** the C# defect is a hardware finding and the nusb path has not met the dongle. | hardware, **fixed in Rust** |
| `SettingsStore` setters | Each setter changes the field before persisting, outside the lock, so a concurrent save (the poll thread writes batching notes) can write a half-updated state. The Rust holds the lock across change and write. **Rust now:** Already fixed before this pass: the lock is held across change and write (threaded tests in `settings_store`). | w1-stores, **fixed in Rust** |
| `MaxxUsbProtocol.Request` | Builds any command, including 0x2F, which erases the ECU flash; it was safe only because no caller passed it. The Rust refuses 0x2F outright. **Rust now:** Already fixed before this pass: `request` refuses 0x2F outright. | w1-ms-maxx review, **fixed in Rust** |
| `DialogCondition` | A parenthesised ternary `(a ? b : c)` evaluates the group with `Or()` and comes out Unknown, while the same ternary without parentheses works, so some INI dialog fields may show or hide wrongly. **Rust now:** The Rust parses the inside of brackets with the whole grammar, ternary included, so `(a ? b : c)` evaluates. | w1-ini, **fixed in Rust** |
| `FilterStore.Reload` | A `null` element in filters.json throws a NullReferenceException and the whole file is lost; the Rust skips the element. Non-finite bounds throw on save only after the in-memory list has changed (ported in the same order). **Rust now:** The Rust skips a null element (pinned) and now builds the file's contents before changing the in-memory list, so a non-finite bound is refused with the list unchanged. | w2-filters, **fixed in Rust** |
| `ChannelUnits.IsLambda` | The `":1"` case can never match: `ChannelRoles.Simplify` strips colons first, so `":1"` becomes `"1"` and falls through to the value guess. **Rust now:** The Rust tests the unit as written for `:1` (an air-fuel ratio) before simplifying. | w2-math-channels, **fixed in Rust** |
| `DefinitionImport` ledger (minor) | Unverified against .NET: a character outside the BMP may encode to one `?` in .NET Latin-1 but two in Rust, and a backtick may be escaped differently in the ledger JSON. Both read back fine; neither has been seen in a real definition. **Rust now:** Checked against .NET 10: `Encoding.Latin1` also gives two `?` for a character outside the BMP, so that half was never a difference; the JSON encoder does escape a backtick (`\u0060`), which the Rust now does too. | w2-definitions review, **fixed in Rust** |
| `Obd2Faults.Parse` | Its comment says a zero byte pair is padding and the rest is ignored, but the code only skips that one pair. **Rust now:** The Rust treats a zero pair as the end of that unit's codes, as the comment says; the one oracle reply that put a code after padding (`43 00 00 01 33`) is skipped as an intended divergence. | w2-obd, **fixed in Rust** |
| `SsmParameterFile` | A `null` entry in `parameters` throws a NullReferenceException; the Rust skips it. **Rust now:** Already fixed before this pass: a null entry is skipped; pinned by `a_null_entry_is_skipped_and_the_rest_of_the_file_is_read`. | w2-obd, **fixed in Rust** |
| `RealtimeDecoder` | A negative field offset throws; the Rust returns NaN for that field. Tune settings with keys differing only in case throw; the Rust keeps the last. **Rust now:** Already fixed before this pass: a negative offset is NaN and the last of case-differing keys wins; both now pinned by tests. | w2-obd, **fixed in Rust** |
| `FtdiEcuTransport.Find` | With no MaxxECU present it falls back to the first FTDI device of any kind, so picking MaxxECU USB with a MicroSquirt on an FTDI cable would open the MicroSquirt and send it MaxxECU frames. The Rust only ever opens a device positively identified as a MaxxECU. **Rust now:** Already fixed before this pass (`with_no_maxx_ecu_an_other_ftdi_device_is_never_chosen`). | w2-transports review, **fixed in Rust** |
| `SerialPortNames` (by comparison) | The C# WMI query saw only present devices; a port number reused by a new device was labelled correctly. Keep it that way: the Rust registry rows apply only to ports the live list reports as Bluetooth or unknown. **Rust now:** Not a defect: it records behaviour to keep, and the Rust keeps it (`a_port_setupapi_could_not_describe_inherits_no_registry_row`). No change. | w2-transports review, not a defect |
| `Elm327Source.Recover` | The comment says the "died batching" suspicion must survive a failed proving read, but `Watching` overwrites it with the post-reset value, so the evidence is lost. **Rust now:** The Rust only ever raises the suspicion, so a failed proving read no longer overwrites it with the post-reset value. | w3-connection, **fixed in Rust** |
| `SsmSource.Read` | Once every address has been dropped it returns NaN rows with no error, so a dead link looks healthy. **Rust now:** The Rust returns an error when every address has been dropped, and `recover` gives dropped addresses a fresh start. | w3-connection, **fixed in Rust** |
| `EcuConnectionSettings.RetryPause` | Never read. **Rust now:** The Rust waits `retry_pause` after the link has settled, before each retry. | w3-connection, **fixed in Rust** |
| `EcuConnection.Dispose` | Can close the port mid-write or mid-burn, and `ReadIdentity` could reopen the port after Dispose. The Rust waits for the conversation in flight instead. **Rust now:** Already fixed before this pass (`dispose_from_another_thread_waits_for_the_conversation_in_flight`). | w3-connection review, **fixed in Rust** |
| `MsqWriter` round-trip check | Its round-trip check rounds ties to even while the page encoder rounds half away from zero, so the two can disagree on an exact .5 and the check can pass or fail on the wrong value. **Rust now:** The Rust's check rounds half away from zero, as the encoder does. | w4-tune, **fixed in Rust** |
| `TuneCompare` | Counts NaN cells as differing, even between identical tunes. **Rust now:** The Rust treats two NaN cells as equal. | w4-tune, **fixed in Rust** |
| `EcuTune.Scalars()` | Reads through the declared scale, not the resolved one `Scalar()` uses, so an expression-scaled constant (e.g. `{fuelLoadRes}`) can show differently in the two. **Rust now:** The Rust reads through the resolved constant `scalar` uses. | w4-tune, **fixed in Rust** |
| `LiveSession` recording | A recording write error (e.g. a full disk) counts as an ECU failure but the failure count resets each poll, so the session loops unpaced and never ends. **Rust now:** Already fixed before this pass (`a_recording_that_cannot_be_written_stops_itself_and_the_session_keeps_its_pace`). | w4-live, **fixed in Rust** |
| `LiveSession.Snapshot` | Cached by sample count, which stops changing once the view is full, so the snapshot goes stale. **Rust now:** The Rust caches the snapshot against a change counter instead of the sample count. | w4-live, **fixed in Rust** |
| `LiveSession` stop | Stopping during a reconnect sets the "did not come back" error. **Rust now:** The Rust sets no error when the stop is what ended the reconnect. | w4-live, **fixed in Rust** |
| `MaxxUsbSource` status | ECU status bytes 0 and 1 are read as the local NoAnswer and Uncertain states. **Rust now:** The Rust reads an ECU's 0 or 1 as `Other(0)` / `Other(1)`; only the local no-answer and uncertain cases make `NoAnswer` / `Uncertain`. **Needs the bench:** the C# defect is by reading, and no ECU has been seen answering 0 or 1. Two oracle names (`status_zero`, `status_one`) are skipped as intended divergences. | w4-live, **fixed in Rust** |
| `MaxxCanSource` | If the drop count is unavailable at open it is never counted. **Rust now:** The Rust starts counting from the first read that finds the drop counter, when it did not answer at open. | w4-live, **fixed in Rust** |
| `MaxxTune` write | `offset + length` can overflow int before the ceiling check; the Rust checks in 64 bits. The C# ceiling test (offset ceiling-2, length 4) would still pass with the ceiling one higher. **Rust now:** Already fixed before this pass: the ceiling is checked in 64 bits and both sides of it are pinned (`the_ceiling_is_0xf2e7_and_a_write_ending_on_it_is_the_last_allowed`). | w4-live, **fixed in Rust** |
| `TuningProject.With(TuneVersion)` | Moves a replaced version to the end, so re-burning an old version makes it "latest" and the parent of the next version, breaking the documented oldest-first order. **Rust now:** The Rust replaces a version in place, so the list stays oldest first and `latest` stays the newest recorded. | w5-projects, **fixed in Rust** |
| `DialogCondition` (nesting) | Nothing limited the depth of the recursive parser, so a long run of `(`, `!`, `-` or chained `?:` in an INI condition overflows the stack, which nothing can catch. The same class as the `MathExpression` entry. **Rust now:** nesting past 64 levels is malformed (the verdict Unknown). | Found while fixing the list in Rust, **fixed in Rust** |
